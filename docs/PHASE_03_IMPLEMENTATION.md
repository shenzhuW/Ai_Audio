# Phase 03 实施边界与验收计划

基线为已验收 Phase 02 `530792c4d482287cb6abf76697d9b248a6fce1af`、远程材料 `8e747526bba86b508e4916107b6aebcf2eef337a`。本阶段仅做研究来源、证据与轻量内容索引，不扩展完整文稿、素材引擎、正式剪辑或自由代码执行。

1. 增量添加 Source、Claim、ClaimEvidence、ResearchIndexEntry 四个实体表；绑定具体 research revision，使用原 Workflow 项目锁、事务、审批、幂等和 Outbox。原表/迁移不改写；新增 PostgreSQL migration 和 SQLite 增量建表，先在全新隔离测试库验证。
2. 草稿中可上传资料、标注来源与限制、编辑 Claim、关联支持/反驳/背景证据。研究实体纳入 contentHash；批准后实体也只读。fork 复制快照、重映射修订内实体 ID，复用原 Blob。旧 Phase 01 文本修订无结构化资料仍可读取。
3. 自包含上传接口支持 TXT/MD/PDF/PNG/JPEG/短 MP4；原件私有不可覆写。PDF 页数/文本、图片宽高、视频元数据/稀疏抽帧时间段使用本地真实提取。可替换 Search/Content/Vision Adapter；未配置和显式 Mock 区分，不制造文章 URL、视觉结论或已核实事实。
4. 独立 Research Worker 复用 Job、心跳租约、取消/重试；保存固定输入，禁止迟到结果写入已批准研究。只生成内容索引和少量预览帧，不正式裁剪。
5. 第 03 页显示来源/引用、日期/统计口径/状态、内容索引、分析任务、摘要及历史审核；复用已有 WorkflowPanel。仅实际上传文件可下载，未访问确认的来源 URL 是用户提供备注，不伪装已检索文章。
6. 先写证据/并发/冻结测试，再接入存储、API、提取与 UI。实际运行 PostgreSQL 新迁移两次、SQLite/PG 持久化、旧 HTTP/工作流回归、浏览器验收、类型检查/单元/生产构建。未运行项目明确记录。

事实状态采用 PRD 的未核实/有支持证据/冲突/作废；“有引用支持”不等于独立核实，未实现自动事实核验器，不提供无证据的 verified 写入。文本匹配仅表明引用能在原件提取文本中定位。D-17/D-18 的未知/不可商用标志保留，但不阻断内部测试资料和分析；访问保护保持。
