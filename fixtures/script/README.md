# Phase 04 可复现合成文稿样例

本目录是非敏感测试说明，不是已经核实的现实资料。自动样例由 `tests/script/run.cjs` 创建独立项目/数据库；所有“32 / 64 units”都来自故意冲突的自制文本，不应当作现实结论。

## 入口 A：已有文稿跳过研究

创建项目时选“已有口播文稿”，填写两段（空行分隔）：

```text
为什么这个问题值得解释？

第二段用户原文，只是合成测试。
```

打开第 04 页，点击“导入文稿 / 建立空白草稿”。修改第二段、保存段落草稿、刷新；正文与段落 ID 保留。添加第三段、填写叙事用途/观众收获/画面意图，使用上移/下移调整，再删除不需要的段落并保存。右侧展示估时和目标差异，不代表已生成配音。

提交→批准后正文只读；创建新修订，修改第二段并保存，下方差异显示同一稳定 ID 的正文变化。提交后可填写意见并驳回，再 fork 修改；点击历史版本可读旧批准内容。

## 入口 B：批准研究与双来源事实绑定

1. 创建主题项目，第 03 页建立研究草稿，上传自制 A.txt：`SYNTHETIC TEST ONLY. Capacity is 32 units.` 和 B.txt：`SYNTHETIC TEST ONLY. Capacity is 64 units.`，都选本地真实提取。
2. 建立“合成测试容量为32单位，资料存在冲突”Claim，日期 `2026-10-23`，口径“仅自制合成夹具”、单位 `units`，明确“不是现实测量”。A 支持引用 32，B 反驳引用 64，位置填各自第 1 段；状态为存在冲突。提交/批准研究。
3. 第 04 页点击“从批准研究建立草稿”（只是摘要导入，不是 AI）；按段编辑，选第二段，在右侧勾选 Claim，保存。展开“查看 Claim 来源与引用位置”，可见两条原文和受保护原件链接、日期/口径及冲突提示。
4. 保存后选择“显式 Mock 结构演示”，点击“仅改写当前段落”；运行 `pnpm worker`，只有目标段落被替换，稳定 ID 与引用保留，结果明显标 Mock。“真实模型 · 未配置”应产生 PROVIDER_NOT_CONFIGURED，不生成文字。
5. 批准文稿后，在研究页面 fork/修改/批准研究新版。回到文稿页显示旧依据及绑定段落影响，旧批准版仍不可改；fork 文稿选择新研究后旧 Claim ID 被清空、需要重绑确认，不自动猜测新旧 Claim 对应关系。

自动验收：`pnpm build` 后执行 `pnpm test:script`；按数据库说明启动独立测试集群，再运行 `node tests/script/run.cjs --postgres`。测试只创建隔离合成数据，模拟下游依赖记录不代表已实现音频或导演模块。
